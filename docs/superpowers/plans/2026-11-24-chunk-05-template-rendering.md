# Chunk 5: Template Rendering Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** The core renders a workspace's managed files: the root `AGENTS.md` and `CLAUDE.md`, `.mesh/`, the client copies of skills and agents for Claude Code and Copilot, a generated `.gitignore` block and seed files. It records every managed file with its hash in `.mesh/render.json`, and it renders new personal and shared brains. Rendering twice is a no-op.

**Architecture:**
- Rendering is split into a pure planner and a thin writer.
  - `planWorkspace` turns the loaded `WorkspaceModel`, the core's template, skill and agent sources and the user's `.local/` sources into a list of `RenderEntry {path, kind, content}`.
  - `renderWorkspace` compares that list with the files on disk and with the previous render record, writes what changed, removes managed entries that have gone, and writes the new record.
- The writer enforces ownership: it only writes into a path that is in the previous record, is missing, or carries the `generated by brain-mesh` marker. It never writes through a symlink.
- New brains are rendered by `brainFiles`, which reuses the chunk 4 generators on an empty brain, so a fresh brain passes `doctor` by construction.

**Tech Stack:** TypeScript ESM, Node ≥22.12, `yaml` 2, `node:crypto` (sha256), Vitest 5. No new dependencies.

## Global Constraints

- Node 22 LTS or newer; no new runtime dependency (libraries: `commander`, `zod`, `yaml`, `mdast-util-from-markdown`, `execa`).
- Windows and Linux are first-class: paths go through Node's `path`; recorded paths are workspace-relative POSIX.
- Generated instructions and skills invoke the CLI as `npx -y brain-mesh@<pinned>`, where `<pinned>` is `mesh.yaml`'s `brain_mesh`.
- Skills use the Agent Skills format: `name` equals the folder name, lowercase letters, digits and hyphens, at most 64 characters. `description` is required, at most 1024 characters.
- Agent source format: frontmatter `name` (= file stem), `description`, and `tools` from `read | search | edit | execute`. Tools map to:

  | Abstract | Claude | Copilot |
  | --- | --- | --- |
  | `read` | `Read` | `read` |
  | `search` | `Grep, Glob` | `search` |
  | `edit` | `Edit, Write` | `edit` |
  | `execute` | `Bash` | `execute` |

  `model` is omitted.
- Client targets:
  - skills go to `.claude/skills/<n>/` and `.github/skills/<n>/`;
  - agents go to `.claude/agents/<n>.md` and `.github/agents/<n>.agent.md`.
- Rendering writes only entries in its render record. Everything else in `.claude/` and `.github/` belongs to the user. Gitignore per rendered entry, not the whole folder.
- `.local/` instructions are concatenated into the generated `AGENTS.md`. A `.local` skill or agent with a core name replaces the core one entirely.
- Obsidian template: `brains/.obsidian/app.json` = `{"useMarkdownLinks": true, "newLinkFormat": "relative", "alwaysUpdateLinks": true}`. It is user-editable, so it is never overwritten.
- `.gitattributes` forces LF: `* text=auto eol=lf`.
- Everything generated inside a brain depends only on the brain `schema`, never on the core version (ADR 0001).
- Determinism: output is sorted by code-unit order, uses `\n` and contains no timestamps.

## Rulings in this plan

1. **No new CLI command.** The spec has none for rendering; `init` (chunk 6), `mount` (chunk 9) and `upgrade` (chunk 11) call `renderWorkspace`. Chunk 5 delivers the library plus tests.
2. **Core sources ship in the package** under `templates/`, `skills/` and `agents/` at the repo root (added to `package.json` `files`). Chunk 5 ships no real skill or agent: those arrive in chunks 7 and 10. Missing `skills/` or `agents/` folders read as empty. Tests use a fixture core in `test/fixtures/core/`.
3. **Entry kinds in the render record:**

   | Kind | Behaviour |
   | --- | --- |
   | `managed` | Rewritten on every render. |
   | `seed` | `.gitattributes` and `brains/.obsidian/app.json`. Written only when missing, never overwritten, never removed. |
   | `block` | The `# brain-mesh:managed` block of `.gitignore`; text outside the block is the user's. |

   The recorded `sha256` is the hash of what brain-mesh rendered (the block body for `block`). For a seed that is the template text even when the user's file differs, so chunk 11 can tell hand edits apart.
4. **Ownership:** a managed path is written only when one of these holds; otherwise it is skipped with warning `W_RENDER_PATH_TAKEN` and left out of the record:
   - it is in the previous record;
   - it does not exist;
   - its text, with CRLF normalised to LF, already equals the rendered text;
   - its text contains `generated by brain-mesh`.

   A symlink at a target path is always skipped with that warning.
5. **Stale entries:** a `managed` entry that is in the previous record but not in the new plan is deleted. Skill folders left empty are removed up to `.claude/skills` and `.github/skills`. Nothing outside the previous record is ever deleted.
6. **Substitution:** only `{{cli}}` is replaced, by `npx -y brain-mesh@<pinned>`, and only in `SKILL.md`, agent bodies and core templates. Every other file in a skill folder is copied byte for byte. Other `{{…}}` text (Obsidian template syntax, for example) is left alone. A core test asserts that no `{{` remains in rendered core templates.
7. **`.mesh/` content:**
   - `.mesh/skills/<n>/**` and `.mesh/agents/<n>.md` are copies of the **core** sources, so `upgrade` can diff overrides later;
   - `.mesh/templates/notes/<type>.md` holds the note templates;
   - `.mesh/render.json` is the record;
   - `.mesh/tools/` and `.mesh/hooks/` are not rendered here: tools arrive later, hooks arrive in chunk 6.
8. **Note templates** live in the workspace at `.mesh/templates/notes/<type>.md`, one per note type, not inside brains. Spec 5.1 fixes a brain's folders, and brains hold only content (ADR 0003). Skills (chunk 7) read them.
9. **The version is `mesh.yaml`'s pin**, used for `{{cli}}` and the record's `brain_mesh`, even when the running core differs. `upgrade` bumps the pin before it renders.
10. **The mount table in `AGENTS.md`:**
    - it lists `personal` first, then the mounts in `mesh.yaml` order;
    - the description comes from each brain's `brain.yaml`, or is `(not cloned)` when the folder or manifest is missing;
    - the published column is `yes` when the mount has a `url`, else `no`; `personal` gets `—`.
11. **`brain.yaml` header URL:** `# yaml-language-server: $schema=https://unpkg.com/brain-mesh/schemas/brain.schema.json`. It is unversioned so brain content stays core-independent (ADR 0001). It resolves once the package is published (chunk 12).
12. **No empty folders in new brains:**
    - `inbox/`, `daily/`, `areas/`, `maps/`, `projects/` and `sources/` appear when the first note is written;
    - no `.gitkeep` files;
    - a new brain is `brain.yaml`, `AGENTS.md`, `CLAUDE.md`, `index.md`, plus `CODEOWNERS` when the brain is shared.
13. **`replaceBlock` gains a comment style:** a `style: 'html' | 'hash'` parameter, default `'html'`. In hash style the markers are `# brain-mesh:<name>` and `# /brain-mesh:<name>`, and `name` widens to include `'managed'`. It is reused for `.gitignore`.

## Review Focus

1. **User-owned files next to rendered ones.**
   - A user's own `.claude/settings.json`, `.claude/skills/my-skill/` or `.github/workflows/ci.yml` survives every render byte for byte.
   - A user's own folder at a core skill's target path is not overwritten (`W_RENDER_PATH_TAKEN`).

   *(Task 3 tests)*
2. **A Windows checkout with CRLF working-tree files** (autocrlf) does not make a render rewrite `AGENTS.md`, and the record is identical on both OSes. *(Task 3 test `CRLF managed file is not rewritten`; the record test runs in CI on both OSes)*
3. **Removing a `.local` override or a core skill.**
   - After a `.local` override is removed, the next render brings back the core version.
   - When a skill disappears from the core, its client folders are deleted, and nothing else under `.claude/` is.

   *(Task 3 tests)*
4. **A symlink at a target path** (for example `.claude/skills/ask` linked to the user's dotfiles) is never written through. *(Task 3 test, skipped where symlinks need privileges)*
5. **The published package contains the templates**, so an `npx` render doesn't fail with a missing file. *(Task 5 e2e test on the packed tarball)*

### Task 3: Render plan, writer and render record

**Files:**
- Create: `src/render/workspace.ts`, `templates/workspace/gitattributes` (`* text=auto eol=lf\n`), `templates/workspace/obsidian-app.json` (`{"useMarkdownLinks": true, "newLinkFormat": "relative", "alwaysUpdateLinks": true}` pretty-printed with two spaces plus `\n`)

**Interfaces:**
- Consumes: Tasks 1–2; `loadWorkspace`; `replaceBlock(..., 'hash')`; `withEol` (chunk 4).
- Produces:
  ```ts
  export type EntryKind = 'managed' | 'seed' | 'block';
  export interface RenderEntry { path: string; kind: EntryKind; content: Buffer }   // block: content = block body
  export interface RecordEntry { path: string; kind: EntryKind; sha256: string }
  export interface RenderRecord { version: 1; brain_mesh: string; files: RecordEntry[] }   // files sorted by path
  export const RECORD_PATH = '.mesh/render.json';
  export function planWorkspace(ws: WorkspaceModel, core: { skills: SkillSource[]; agents: AgentSource[]; templates: CoreTemplates }, local: { skills: SkillSource[]; agents: AgentSource[]; instructions: LocalInstruction[] }): RenderEntry[];
  export interface CoreTemplates { agentsMd: string; gitattributes: string; obsidianApp: string; notes: Map<string, string> }   // notes: "<type>.md" → text; an absent templates/notes/ gives an empty map until Task 4 adds the files
  export interface RenderResult { written: string[]; removed: string[]; record: RenderRecord; warnings: Warning[] }
  export function renderWorkspace(root: string, opts?: { core?: CoreSource }): Promise<RenderResult>;
  ```
- `planWorkspace` produces these entries, all under the pinned `cli`:
  - **managed:**
    - `AGENTS.md`;
    - `CLAUDE.md` = `@AGENTS.md\n`;
    - `.mesh/skills/<n>/<f>` and `.mesh/agents/<n>.md` (core copies, unfilled);
    - `.mesh/templates/notes/<type>.md`;
    - for each skill in `overlay(core, local)`: `.claude/skills/<n>/<f>` and `.github/skills/<n>/<f>` from `skillFiles`;
    - for each agent in `overlay(core, local)`: `.claude/agents/<n>.md` (`claudeAgent`) and `.github/agents/<n>.agent.md` (`copilotAgent`).
  - **seed:** `.gitattributes`, `brains/.obsidian/app.json`.
  - **block:** `.gitignore`, whose body is `gitignoreBlock(ws, clientPaths)`. The client paths are each rendered skill folder (`.claude/skills/<n>/`, `.github/skills/<n>/`) and each agent file.
- `renderWorkspace`:
  1. It loads the workspace, and throws `CliError(ErrorCode.NoWorkspace, …, ExitCode.Failure)` when `mesh.yaml` is missing or invalid.
  2. It reads the core (default `packageCore()`) and `.local/skills`, `.local/agents` and `.local/*.md`. Source problems become warnings `W_SKILL_INVALID` or `W_AGENT_INVALID`, naming the path.
  3. It reads the previous record. A missing or unparsable record counts as empty.
  4. It applies Rulings 3–5. A path is written only when its LF-normalised current text differs from the rendered text, or the file is missing. A CRLF current file that is otherwise equal is left alone, and a rewritten one gets `withEol`.
  5. It writes per file, and turns failures into `W_WRITE_FAILED` warnings. It creates new files with the `wx` flag, and checks with `lstat` before overwriting.
  6. It writes the record only when its JSON text changed. The format is `JSON.stringify(record, null, 2) + '\n'`.
- `written` and `removed` are workspace-relative POSIX paths, sorted, and include the record when it was written.
