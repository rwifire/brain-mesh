# Generated MOC lists travel inside each contributor's PR

Generated parts of a shared brain (MOC lists, `CODEOWNERS`, `links_to`) are regenerated by `doctor --fix` on the contributor's machine and committed in the same PR as the content change. When two PRs conflict inside a generated block, the CLI resolves it by regenerating rather than merging text. We chose this over a post-merge bot commit to main (would put CI and an unreviewed writer into v0) and over freshness-check-only CI with periodic regeneration PRs (lists would lag behind content). It works because v0 has low PR volume in one team; revisit if conflicts become frequent.

## Consequences

- Generator output must be deterministic and sorted, and depend only on the brain's `schema` version, never on the core version, so contributors on different core versions don't churn each other's files.
